# Скилл `making-store-screenshots`: дизайн

Дата: 2026-11-26. Статус: на утверждение автора (после проверки строителем).

## Зачем

Скилл для людей, которые ставят себе скиллы из каталога `LinDevHard/agent-skills`. Агент в **любом** проекте
(Android, iOS, кроссплатформа, веб) собирает серию маркетинговых скриншотов для сторов — такую, какую сейчас
делают в Figma или руками в Pixstage: обложка, по одной функции на кадр, единый стиль, композиция, которая
продолжается через стык кадров. Результат сразу годится для загрузки: правильные размеры, без альфы, без
запрещённых сторами слов, в той папке, откуда его возьмут fastlane и сторы.

Визуальная планка — референсы, которые выбрал автор (особенно первые два):
- **Pandora** (App Store): светлый фон, рукописные заголовки с цветным маркером, рисованные завитки и стрелки,
  которые заходят на соседний кадр.
- **Themify**: фон каждого кадра в тон его скриншоту, заголовок с засечками, обложка на два кадра, телефоны
  крупные и уходят за нижний край.
- **Ladder**: жирный капс, тёмные кадры, градиент на обложке, по два телефона внахлёст.

Стиль и приёмы берутся из Pixstage (раскладки 1–3 снимков, фоны, цвета из скриншота, наклон, тени, «на столе»),
но сам Pixstage скиллу не нужен.

## Цели

1. Найти или снять исходные скриншоты: папка пользователя → готовые снимки в проекте → съёмка с эмулятора,
   симулятора или браузера с чистым статус-баром.
2. Написать короткие подписи под ASO для каждой локали листинга и показать их на утверждение.
3. Собрать серию 5–8 кадров в одном из стилей, с обложкой и сквозной композицией (панорамой).
4. Отрендерить её в размерах каждого нужного стора и проверить по правилам сторов.
5. Положить файлы в fastlane-дерево проекта.

## Не цели

- Загрузка в сторы (для этого `publishing-bundle-to-play` / `-rustore`).
- AI-генерация фонов и любые сетевые запросы во время работы скилла.
- Видео-превью.
- Wear OS, TV, Automotive, XR, Mac, Vision Pro, Apple Watch (первая версия: телефоны, планшеты, feature graphic).
- Редактор с UI. Правки — через диалог с агентом и конфиг серии.

## Анти-цели (провал, даже если «работает»)

- Нарисованные бейджи сторов, «Featured by Apple», «Editor's choice», награды, рейтинги, отзывы, число скачиваний
  — даже если пользователь просит; можно только то, что пользователь даёт как реальный факт и что разрешено
  правилами стора (в Play — нельзя вовсе). Это фальшивка и причина отказа.
- Рамка, похожая на iPhone или конкретный Android-телефон (остров, вырез, кнопки, логотипы).
- Android-снимки или слово «Android» в наборе для App Store (Apple 2.3.10).
- Скриншоты, которые не показывают реальный интерфейс (только арт, заставка, логин).
- Кадры, которые при выкладке подряд не сходятся на стыке.
- Скилл, который каждый раз выдаёт разное качество: стиль задаётся шаблоном, а не сочиняется агентом с нуля.

## Ограничения

- Работает в любом проекте без Android Studio и JDK. Зависимости: Python 3, `playwright` (Chromium) и `Pillow`.
  Скилл проверяет их и даёт точную команду установки (локально, в venv, не глобально).
- Без сети во время рендера: шрифты (OFL, с кириллицей) и SVG-декор лежат в скилле.
- Формат Agent Skills (agentskills.io), как остальные скиллы каталога; работает в Claude Code, Codex и через
  `npx skills`.
- Все рекомендации Anthropic по авторингу скиллов (раздел «Требования к самому скиллу» ниже).

## Подходы (рассмотрены, выбран A)

| | Подход | Плюсы | Минусы |
|---|---|---|---|
| **A (выбран)** | HTML/CSS-шаблоны стилей + рендер через headless Chromium (Playwright) | Лучшая типографика и эффекты (градиенты, 3D-наклон через `perspective`, тени, blur), любые языки, агенту легко подстроить под бренд; так уже собрана feature graphic Pixstage | Нужен Chromium (ставится одной командой) |
| B | Python + Pillow, без браузера | Минимум зависимостей | Слабые текст, градиенты, тени, нет честного 3D-наклона; заметно хуже Pixstage |
| C | Только инструкции, агент каждый раз пишет HTML/SVG сам | Гибкость | Качество скачет, проверять нечего |
| — | JVM/Skia CLI из настоящего `drawScene` Pixstage | Тот же движок, что в приложении | JDK, сборка, не подходит для «любого проекта» |

Автор выбрал A.

## Решения автора

- Скилл для людей, работает в любом проекте.
- Движок: HTML/CSS + headless Chrome (A).
- Единица работы — **серия** 5–8 кадров, первый кадр — обложка (может занимать два кадра), дальше одна функция на
  кадр; на одном кадре может быть до трёх снимков, как в Pixstage.
- **Сквозная композиция**: один скриншот может быть разрезан между двумя кадрами (половина на одном, половина на
  следующем), фон и декор (линии, завитки) продолжаются на следующих кадрах.
- Ориентиры по стилю: Pandora и Themify в первую очередь, стили должны быть разными.
- **Рамка — нейтральная**: скруглённый корпус без острова, выреза, кнопок и логотипов; наклон разрешён.
- Правила сторов — по официальным страницам, записаны требованиями (ниже) и в `references/store-rules.md`.
- Съёмка Android — через `android screen capture`, если установлен Android CLI, иначе `adb`.

## Как работает скилл (поток агента)

Чеклист, который агент копирует и отмечает (паттерн из рекомендаций Anthropic):

1. **Цели.** Какие сторы и устройства: определить по проекту (Android-модуль → Play/RuStore/AppGallery/F-Droid,
   Xcode-проект → App Store, iPad — если `TARGETED_DEVICE_FAMILY` включает 2; планшеты Android — только если есть
   снимки планшета). Локали — по существующему дереву листинга, иначе спросить.
2. **Источник снимков**, по порядку:
   - папка, которую дал пользователь;
   - готовые снимки в проекте (`fastlane/screenshots`, `fastlane/metadata/android/*/images`, `store/`,
     `screenshots/`, `docs/`) — показать найденное и спросить, их ли брать;
   - съёмка: Android — `android screen capture -o` или `adb exec-out screencap -p`, iOS —
     `xcrun simctl io booted screenshot`, веб — Playwright. Перед съёмкой — чистый статус-бар (Android demo mode,
     `xcrun simctl status_bar override`), после — вернуть как было. Навигацию по экранам агент делает сам
     (`android layout`, тапы, deep links) или просит пользователя вывести нужный экран.
   - Если у снимков из папки грязный статус-бар — предложить обрезать системные полосы (`crop` в конфиге).
3. **Порядок и подписи.** Агент выбирает 5–8 экранов (сильнейший — на обложку, первые три показывают UI) и пишет
   подписи: ключевые слова берёт из описания листинга (`fastlane/metadata/.../full_description.txt`, README).
   Заголовок 2–5 слов, одна выгода, без запрещённых слов. Показывает таблицу «кадр → экран → подпись» по всем
   локалям и ждёт утверждения.
4. **Стиль.** Предложить один из стилей (по характеру приложения и его цветам) с одной фразой «почему», показать
   превью обложки, дать выбрать другой.
5. **Конфиг серии.** Агент пишет `series.json` (схема ниже) в рабочую папку (по умолчанию `store/screenshots/`
   проекта), затем `scripts/render.py --validate` проверяет его до рендера (план → проверка → исполнение).
6. **Рендер** всех целей одной командой.
7. **Проверка.** `scripts/check.py` по правилам сторов; затем агент **смотрит** на контактный лист (одна картинка
   со всеми кадрами вплотную, рендерится вместе с серией) и проверяет глазами: стыки сходятся, текст не налезает,
   UI читается. Ошибки → правка конфига → шаг 6. Дальше только когда `check.py` без FAIL.
8. **Выкладка** в fastlane-дерево и итог пользователю: что где лежит, что осталось (например, загрузить вручную).
   Не коммитить.

## Стили (первая версия — четыре)

Стиль — это **рецепт серии**: шрифты, фон, как меняется цвет от кадра к кадру, декор, как выглядит обложка и
обычный кадр. Каждый стиль — HTML/CSS-шаблон в `assets/styles/<style>/`.

- **sketch** (по Pandora): светлый фон, рукописный заголовок с цветным маркером-подложкой, маркер меняет цвет по
  палитре от кадра к кадру; SVG-дудлы (завитки, стрелки, искры), часть которых переходит через стык; телефоны с
  лёгким наклоном.
- **tone** (по Themify): фон кадра — мягкий градиент из доминирующих цветов его скриншота; заголовок с засечками;
  обложка на два кадра с крупными телефонами внахлёст через стык; телефоны уходят за нижний край.
- **poster** (по Ladder): тёмные кадры, жирный капс, яркий акцент бренда, градиент на обложке, до двух телефонов
  внахлёст.
- **minimal** (стиль Pixstage): ровный градиент или цвет, аккуратная подпись, один крупный телефон с тенью,
  без декора.

Общее для всех: подпись сверху; телефон крупный и может уходить за нижний край; цвет бренда — из конфига, иначе
из иконки приложения или скриншотов (доминирующие цвета).

## Рамка устройства

Нейтральная: скруглённый прямоугольник-корпус с тонкой тёмной рамкой и скруглённым экраном, без острова,
выреза, кнопок, камеры и логотипов (Apple запрещает имитацию своих устройств, Google не рекомендует изображения
устройств вообще). Варианты: `phone`, `tablet`, `none` (только скруглённый скриншот с тенью). Наклон (2D-поворот и
3D-tilt), тень, «на столе» — из приёмов Pixstage.

## Сквозная композиция (панорама)

Серия рисуется как **один холст** шириной `N × ширина кадра` в координатах цели; элементы ставятся в координатах
холста и могут пересекать границы кадров. Рендер режет холст точно по границам (без зазоров и перекрытий), поэтому
в сторе кадры снова сходятся. Для каждой цели холст строится заново в её пропорциях (iPhone ≈ 0,46, Android 0,5625),
поэтому шаблоны задают позиции в относительных единицах кадра, а не в пикселях.

## Конфиг серии (`series.json`)

Схема — забота строителя; должны быть выражены:

- `app`: имя, цвета бренда (необязательно), путь к иконке (необязательно);
- `style`: имя стиля и необязательные переопределения (шрифт, палитра, тёмный/светлый);
- `targets`: список целей из таблицы размеров (`ios-phone`, `ios-ipad`, `android-phone`, `android-tablet`,
  `feature-graphic`);
- `locales`: список; подписи задаются по локалям;
- `frames`: упорядоченный список кадров: роль (`cover` / `feature`), ширина в кадрах (1 или 2 для обложки),
  1–3 снимка с раскладкой, поворотом/наклоном, `crop` (обрезка системных полос), подпись и подзаголовок по локалям;
  разные снимки для iOS и Android, если они есть;
- `decor`: сквозные элементы, которые пересекают стыки (их позиции в координатах холста);
- `output`: куда писать (по умолчанию — fastlane-дерево проекта).

## Цели рендера и выкладка

| Цель | Размер (портрет) | Куда |
|---|---|---|
| `ios-phone` | 1320×2868 и 1206×2622 (одна вёрстка, пропорции совпадают) | `fastlane/screenshots/<locale>/` (имена, по которым `deliver` узнаёт размер) |
| `ios-ipad` | 2064×2752 | `fastlane/screenshots/<locale>/` |
| `android-phone` | 1080×1920 (9:16) — один набор для Play, RuStore, AppGallery, F-Droid | `fastlane/metadata/android/<locale>/images/phoneScreenshots/1.png…` |
| `android-tablet` | 1200×1920 (7") / 1600×2560 (10") в 9:16-совместимом виде — точные размеры решает строитель по правилам ниже | `sevenInchScreenshots/`, `tenInchScreenshots/` |
| `feature-graphic` | 1024×500 | `fastlane/metadata/android/<locale>/images/featureGraphic.png` |

Если в проекте уже есть дерево (fastlane, Triple-T `src/main/play/listings/...`) — писать в него. Если нет —
создать fastlane-дерево и сказать об этом. Существующие файлы — не перезаписывать без вопроса.

Плюс в рабочей папке: `contact-sheet.png` (вся серия вплотную) и `alt-text.<locale>.txt` (alt-текст Play,
≤140 символов на кадр, не начинается с «image of / photo of»).

## Требования сторов (проверено по официальным страницам 2026-11-26)

### App Store
- Обязательно: ≥1 снимок для **iPhone с Dynamic Island (medium)** — 1206×2622 или 1179×2556; iPad 13" —
  2064×2752 или 2048×2732, если приложение есть на iPad. Остальные размеры стор масштабирует сам.
- 1–10 снимков на размер дисплея; JPEG или PNG; **без альфа-канала и прозрачности**.
- 2.3.3: снимки показывают приложение в работе, не только титульный арт, логин или заставку; текстовые оверлеи
  разрешены.
- 2.3.7: никаких цен и условий в снимках. 2.3.14: никаких непроверяемых заявлений и скидок.
- 2.3.8: контент снимков — уровня 4+, даже если приложение взрослое.
- 2.3.9: только вымышленные данные аккаунтов, права на все материалы.
- 2.3.10: никаких имён, иконок и изображений других мобильных платформ и магазинов (Android, Google Play).
- Маркетинговые гайды Apple: нельзя рисовать, симулировать и изменять изображения устройств Apple, нельзя бейджи
  кроме официального App Store-бейджа; статус-бар — полные сеть, Wi-Fi, батарея.
- iPhone Duo: с апреля 2027 обязателен для приложений на iOS 27.1 SDK+ (вне первой версии; отметить в
  `store-rules.md`).

### Google Play
- Формат: JPEG или 24-битный PNG без альфы; сторона 320–3840 px; длинная сторона ≤ 2,3 × короткой; ≤ 8 МБ.
- Телефон: 2–8 снимков. Для рекомендаций и подборок — **≥4 снимка не меньше 1080 px** (портрет ≥1080×1920).
- Планшеты 7" и 10": ≥4 снимка, стороны 1080–7680 px, 9:16 или 16:9.
- Feature graphic: ровно 1024×500, без альфы; ключевое ближе к центру; без бейджей и устройств.
- Подпись занимает **≤20 % площади** кадра; без мелкого текста и фона, который спорит с текстом.
- Нельзя: «Best», «#1», «Top», «New», «Discount», «Sale», «Free», «Million downloads», любые рейтинги, награды,
  отзывы; призывы «Download / Install / Play / Try now»; временной контент; бейджи Google Play и других сторов;
  чужие логотипы и знаменитости без разрешения.
- Чистый статус-бар: без уведомлений и оператора, полные батарея, Wi-Fi и сеть.
- Без размытия, растяжения и пережатия; правильная ориентация.
- UI, разрезанный между кадрами, разрешён; первые три кадра — про интерфейс.
- Подписи локализуются; alt-текст ≤140 символов.

### RuStore
- Снимки телефона обязательны; **≥3** на каждый тип устройства; загрузка до 10 за раз.
- PNG или JPG; **≤3 МБ** телефон, ≤5 МБ планшет; максимум 2160×3840.
- Рекомендуемое соотношение 16:9 — иное **растягивается или обрезается**, поэтому только 9:16 / 16:9.

### Huawei AppGallery
- 3–8 снимков; PNG/JPG **≤2 МБ**; стороны 320–3840 px; разрешение в справке — 450×800 (портрет).

### F-Droid
- PNG или JPEG; `fastlane/metadata/android/<locale>/images/phoneScreenshots/1.png…`; размеров и количества
  не задаёт.

### Что из этого следует для скилла
- Один Android-набор 9:16 (1080×1920) подходит всем четырём Android-сторам; если PNG тяжелее 2 МБ, писать JPEG
  (качество подбирается до лимита) — лимит AppGallery самый строгий.
- По умолчанию 6 кадров: ≥4 для Play-рекомендаций, ≥3 для RuStore и AppGallery, ≤8 для Play и AppGallery.
- iOS-набор — отдельный, только из iOS-снимков (или из веб/кроссплатформенных снимков без Android-хрома).

## `scripts/check.py` — что проверяет

Детерминированно, с понятными сообщениями (`FAIL`/`warn` + что исправить):

- размеры по цели, пропорции, сторона 320–3840, длинная ≤2,3× короткой;
- отсутствие альфы; вес файла против лимитов (8 МБ Play, 3 МБ RuStore, 2 МБ AppGallery);
- число кадров против минимумов и максимумов выбранных сторов;
- подписи: запрещённые слова (EN и RU, словарь в скрипте; другие локали — `warn` «проверь вручную»), цены и
  проценты, призывы к установке, длина;
- доля площади подписи ≤20 % (рендер отдаёт геометрию текстовых блоков);
- контраст подписи к фону (≥4,5:1 `warn`, <3:1 `FAIL`);
- текст не в верхних и нижних 5 % кадра;
- апскейл исходника больше 1,5× — `warn`;
- в целях iOS нет снимков с пометкой `platform: android`;
- на стыках кадров нет зазора (срезы совпадают пиксель в пиксель с холстом);
- alt-текст есть и ≤140 символов.

## Требования к самому скиллу (рекомендации Anthropic и agentskills.io)

- Каталог: новый плагин `store-assets` в `~/Develop/agent-skills/plugins/` (скилл не только про Android); оба
  манифеста плагина, обе marketplace-записи, строка в таблице README, `claude plugin validate .`.
- Путь: `plugins/store-assets/skills/making-store-screenshots/` с `SKILL.md`, `references/`, `scripts/`, `assets/`.
- `name: making-store-screenshots` (герундий, как в каталоге; совпадает с папкой; без `--`, без
  `claude`/`anthropic`).
- `description` в третьем лице, ≤1024 символов, без XML: что делает (серия маркетинговых скриншотов для App Store,
  Google Play, RuStore, AppGallery, F-Droid из снимков приложения) и когда (просят store screenshots,
  скриншоты для стора, ASO-скриншоты, feature graphic); и когда не надо (загрузка в стор, обычный скриншот экрана).
- `SKILL.md` < 500 строк и < 5000 токенов: поток-чеклист, правила, которые агент не знает сам; без объяснений
  очевидного. Одна терминология: «серия», «кадр», «снимок» (исходный скриншот), «цель», «стиль».
- `references/` — один уровень, каждый файл с оглавлением, если длиннее 100 строк:
  `store-rules.md` (правила с датой проверки и ссылками), `capturing.md` (команды съёмки и чистого статус-бара по
  платформам), `styles.md` (стили с превью и когда какой), `copywriting.md` (подписи: примеры вход → выход на EN
  и RU, запреты). Даты и сменяющиеся правила — только в `store-rules.md`, с пометкой «проверено <дата>».
- `scripts/` запускаются, а не читаются (сказано явно): `render.py` (`--validate`, рендер, контактный лист),
  `check.py`, `palette.py` (если строитель вынесет его отдельно), при необходимости `statusbar.sh`. Скрипты сами
  обрабатывают ошибки (нет Chromium — точная команда установки; нет файла — список найденных), без «магических
  чисел» без комментария.
- `assets/`: шаблоны стилей, шрифты OFL с лицензиями, SVG-декор.
- Степень свободы: низкая для рендера и проверки (точные команды), высокая для выбора экранов и подписей.
- Обратная связь: validate → render → check → посмотреть на контактный лист → повторить.
- Оценки (evals) — **до** длинной документации, минимум три, с базовой линией «без скилла», прогон на Haiku, Sonnet
  и Opus:
  1. папка с 6 Android-снимками, локали en-US и ru-RU → серия для Play в стиле tone, fastlane-дерево;
  2. iOS-проект с запущенным симулятором → съёмка с чистым статус-баром, серия sketch для iPhone и iPad;
  3. проект с готовыми снимками в `fastlane/` и просьбой «чтобы телефон переходил на второй кадр» → панорамная
     обложка, стыки сходятся;
  4. просьба «напиши на первом кадре #1 приложение, бесплатно» → скилл отказывается и предлагает допустимую
     формулировку;
  5. Android-снимки и просьба сделать набор для App Store → предупреждает о 2.3.10 и не кладёт их в iOS-набор.
- Безопасность: скилл не ходит в сеть при рендере, не загружает ничего в сторы, не коммитит.

## Порядок работы и приёмка

**Решение автора:** стили утверждаются глазами до всего остального. Сначала четыре шаблона и минимальный
`render.py`; каждый стиль рендерится на скриншотах Pixstage (`~/Develop/rinwave/shotly/store/listing/source/`,
`store/listing/google-play/phone/`) в контактный лист из 6 кадров вплотную, как референсы. Автор смотрит и правит;
только после его «да» — `check.py`, `SKILL.md`, references, evals. Итоговая приёмка — evals проходят **и** автор
принял контактные листы.

## Решения, принятые при проверке дизайна (мои, автор может поправить)

- **Evals.** Формат — как в `skill-creator` (`evals/evals.json`: prompt, файлы, ожидаемое поведение-рубрика), лежат
  в репозитории вне плагина: `evals/making-store-screenshots/` (чтобы `npx skills` их не ставил). Фикстуры: набор
  снимков Pixstage (Android) и маленький iOS-проект-заглушка (SwiftUI, 3 экрана) для eval 2 — он запускается только на
  macOS с Xcode, остальные везде. Интерактивные остановки снимаются промптом («подписи утверждаю, стиль tone»).
  Прогон через сабагентов на Haiku, Sonnet, Opus с базовой линией без скилла.
- **Письменности.** Встроенные шрифты — латиница и кириллица (и греческий, где шрифт его покрывает). Для CJK,
  тайского, деванагари и др. рендер берёт системный шрифт Chromium, `check.py` даёт `warn` «проверь глазами». RTL
  (арабский, иврит) в первой версии без зеркалирования раскладки: `warn`, подпись выравнивается по правому краю.
- **Feature graphic** строится из обложки стиля: тот же фон и декор, иконка приложения, название и одна
  строка-выгода, без устройств и бейджей, ключевое — в центральной зоне; локализуется по локалям.
- **Нет снимков iPad / Android-планшета.** iPad: снять с iPad-симулятора, если он есть; иначе спросить; **никогда**
  не класть телефонные снимки в iPad-набор (Apple отклоняет). Android-планшет: только если есть планшетные снимки,
  иначе пропустить (RuStore покажет телефонные).

## Оставлено строителю

- Точная схема `series.json`, имена полей и раскладок.
- Устройство шаблонов (один HTML на стиль или общий каркас + CSS стиля), как считать доминирующие цвета.
- Набор шрифтов (OFL, с кириллицей; рукописный, с засечками, гротеск, плотный капс) и SVG-дудлов.
- Точные размеры Android-планшетов в пределах правил Play и RuStore.
- Имена iOS-файлов под `deliver`.
- Как именно агент выводит нужный экран перед съёмкой.
- Порог JPEG-качества под лимиты веса.
